Install & Setup

postwisp builds on any machine with the Gossamer toolchain and deploys as one directory: binary, templates, built-in pages, and the setup script.

Prerequisites

Build machine

  • Linux, macOS, or Windows.
  • The Gossamer toolchain, ^v0.58.3 (the version project.toml pins). Install it with:
curl -fsSL https://raw.githubusercontent.com/gossamer-lang/gossamer/main/scripts/install.sh | sh

This installs gos into ~/.local/bin. Make sure that directory is on your PATH — if gos --version does not answer, add it:

export PATH="$HOME/.local/bin:$PATH"
Node is not required. Node.js is only used for the optional development checks (node scripts/check-*.js) — never to build or run postwisp.

Server

  • Linux with curl (used by the setup script and the health check).
  • systemd optionally, for the service install — a system unit with root, or a user unit on a shared VPS without root.

Build

On the build machine:

git clone https://github.com/danpozmanter/postwisp
cd postwisp
./build-deploy.sh             # cross-build for your server (default linux-x64)
./build-deploy.sh linux-arm64 # e.g. an ARM server

On Windows (PowerShell):

.\build-deploy.ps1             # cross-build for your server (default linux-x64)
.\build-deploy.ps1 linux-arm64 # e.g. an ARM server

build-deploy.sh (or build-deploy.ps1) cross-builds for the deployment target — linux-x64 (default, static musl), linux-arm64, macos-arm64, macos-x64, or win-x64 — and sets up the cross-build prerequisites itself. It cleans dist/ before filling it, and --dir=DIR (-Dir DIR in PowerShell) builds into a different directory. To try postwisp on the build machine itself, use ./build-local.sh (.\build-local.ps1 on Windows; native build, same dist/ layout, same --dir=/-Dir option).

Either script assembles the target directory containing:

dist/postwisp            the release binary
dist/templates/          index.html post.html list.html about.html
dist/web/                built-in admin/editor/setup pages
dist/scripts/setup.sh    first-run setup

Deploy

Copy the contents of dist/ to your server — binary, templates/, web/, and scripts/ sitting side by side in one directory. That directory is the whole deployment; everything runs from it.

Set up

On the server:

./scripts/setup.sh

The script walks you through first run:

  1. Bind address — the default 127.0.0.1:8080 keeps the server on loopback, ready for a reverse proxy or SSH tunnel. Set 0.0.0.0:8080 to serve a LAN.
  2. Service — install a systemd system unit via sudo, a user unit on a shared VPS without root (with linger enabled so it keeps running after you log out), or decline. Declining is fine: for local use the script starts the server in the background and completes the same walkthrough. On a non-Linux host, or one without systemd, it also starts the server by hand.
  3. Health check — the script confirms the server is actually up by checking the plaintext status endpoint: curl /status answers postwisp ok.
  4. One-time token — paste the token from the server console (journalctl -u postwisp, or data/server.log in manual mode).
  5. Admin account — pick a username and password. Password policy: minimum 10 characters, at least 1 digit and 1 non-alphanumeric.
  6. Theme — choose the site-wide light or dark default.
  7. Unsplash key — optionally paste a free Unsplash access key (see Media & Unsplash); it is written to an env file beside the binary.

The script finishes by verifying the public pages and printing the management commands for your exact install.

Manage the service

systemctl status postwisp            # or: systemctl --user status postwisp
systemctl restart postwisp           # or: systemctl --user restart postwisp
systemctl stop postwisp              # or: systemctl --user stop postwisp
journalctl -u postwisp -f            # follow the logs
curl http://127.0.0.1:8080/status    # "postwisp ok"
