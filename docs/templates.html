Templates & Theming

Edit the templates in templates/ as you see fit — that is the whole theming story. Each is a plain HTML file with inline CSS (no shared stylesheets, no build step), and the server reads them from disk on every request, so edits show up on the next page load, no restart.

The four templates

TemplateServesNotes
templates/index.html/home page; the 3 most recent posts
templates/post.html/<user>/<slug>one published post
templates/list.html/postsall posts, and /posts?tag=NAME for one tag
templates/about.html/aboutthe frame around the about post

There is no landing.html or post-list.html to find: the home page is templates/index.html, a post is templates/post.html.

Placeholders

{{title}}, {{site_title}}, {{tagline}}, {{footer}}, {{content}}, {{date}}, {{author_part}}, {{tags_part}}, {{theme_attr}}, {{feed_url}} are filled per page; everything else is yours.

The about page

The about page is not a file you edit per se — it is a singleton post each author maintains, with the reserved slug about. Log in to /dashboard, press About page, and write it like any post (markdown, in the same full-width editor with the styled/raw toggle). It is then served at /about (the first user's — the admin's) and at /<user>/about for every author. About pages never appear in the post lists or feeds; templates/about.html only frames them. Until someone writes one, a placeholder fills the frame.

Design tokens

The public templates inline the same token set the built-in admin pages use (/app.css), so a page is one request with no stylesheet dependency. The tokens at the top of each file — the color palette, the fluid clamp() type scale, and the font stacks (Atkinson Hyperlegible for UI, Source Serif 4 for prose, JetBrains Mono for code) — are the theming surface. Both light and dark mode ship; the site-wide default is set on the Settings page, and each visitor's own header toggle takes precedence.
